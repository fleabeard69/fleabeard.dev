0Put the privacy policy and support pages online

Do this first. Apple needs both links, and they must be public web pages.

Two ready-made pages are in the same folder as this guide: privacy-policy.html and support.html. Open each one and replace [CONTACT EMAIL] and [OPERATOR NAME] (whoever runs the Immich server). Then put both pages online in one of these ways:

  1. Your own server (easiest if you run massgrave.cloud): serve them at, for example, https://massgrave.cloud/photoclean/privacy and /photoclean/support.
  2. GitHub Pages (free): create a public repository, upload both files, then turn on Settings → Pages. Your links will look like https://[username].github.io/photoclean/privacy-policy.html.

Open both links in a private browser window to make sure they load without a login.

1Screenshots

App Store Connect → your app → iOS App 1.0 → Previews and Screenshots → iPhone with Dynamic Island (medium display)

Drag in all five, in this order. They are 1206 × 2622 PNGs, in the screenshots-6.3in folder. Apple shrinks them to fit smaller iPhones automatically. Your app is iPhone-only, so there's no iPad slot to fill.

The screens are redrawn from the app's own layout code, with illustrated pictures standing in for real photos. That's normal for App Store screenshots, as long as they show how the app really works, and these do. If you'd rather use real captures, run the app in the iPhone 16 Pro Max (or 17 Pro Max) simulator and press ⌘S. Those come out at the same size.

3Pick the build

Same page → scroll to Build → click + (or "Add Build")

Choose the build you uploaded (version 1.0). If there's no + button or the list is empty, the build is still processing. Wait for Apple's "has completed processing" email and refresh the page.

If it asks about encryption when you add the build, jump to step 9 for the answer.

Make sure it can sign in, and leave it signed up. The reviewer's test device will back up its photos to this account and delete some of them, so don't use your own account.

A possible snag: Apple sometimes questions apps that only work for people who were given an account (guideline 3.2, "limited audience"). The notes above explain the setup honestly. If Apple pushes back anyway, the usual fix is to ask for Unlisted App Distribution (the app only shows up for people with the direct link) instead of a public listing. Mention whether anyone can request an account on your server. That helps your case.

9Encryption (export compliance)

Shown when you add the build or submit, as "App Encryption Documentation"

What type of encryption algorithms does your app implement?None of the algorithms mentioned above

This is correct because the app only uses Apple's built-in encryption: HTTPS, Keychain, and CryptoKit's SHA-1 for file checksums. That's exempt, and no documents are needed.

10Submit

iOS App 1.0 page → top right

  1. Click Save.
  2. Click Add for Review. If anything is still missing, Apple lists it in red. Fix it and click again.
  3. On the next screen, click Submit for Review.

The status changes to Waiting for Review, then In Review (usually within 1 to 2 days), then Pending Developer Release or Ready for Distribution. If Apple has questions, they show up in App Review → Messages and you get an email.
